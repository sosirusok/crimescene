# KISPG 운영 연결 체크리스트

현재 사이트는 예약·결제 상태 모델과 KISPG 연결 여부 확인 API까지 구현되어 있습니다. 실제 카드 승인 요청은 가맹점 계약 이후 KIS정보통신에서 발급하는 기술 문서와 운영/테스트 자격증명을 받은 다음 연결해야 합니다.

## 지금 준비된 범위

- 예약별 `payments` 레코드와 `READY / PAID / FAILED / REFUNDED` 상태
- KISPG 구성 여부를 확인하는 `/api/payments/kis/status`
- 관리자 페이지의 결제 상태 관리 및 결제 완료 매출 집계
- KISPG 연결 전에는 결제 대기 상태로 안전하게 예약 접수
- 카드번호와 카드 인증정보를 자체 데이터베이스에 저장하지 않는 경계

## 계약 후 필요한 정보

1. 운영 MID와 테스트 MID
2. KISPG가 제공한 요청 URL, 승인·취소 URL 및 필드 정의
3. 서명 또는 위변조 검증 방식과 키
4. 결제 완료/실패/취소 콜백 규격
5. 운영 도메인과 콜백 URL 등록 절차
6. 수수료, 정산주기, 보증보험, 가입비·연관리비 유무가 기재된 최종 견적서

위 값은 계약 상품과 심사 결과에 따라 달라질 수 있으므로 추정값으로 구현하지 않습니다. KISPG 기술 패키지를 받으면 `.env.example`의 환경변수 이름을 실제 명세에 맞춰 확정하고, 결제 요청 → 승인 검증 → 콜백 멱등 처리 → 취소·환불까지 통합 테스트해야 합니다.

## 배포 환경변수

```text
ADMIN_EMAILS=허용할 운영자 이메일(쉼표 구분)
PII_ENCRYPTION_KEY=충분히 긴 무작위 비밀값
KIS_MID=가맹점 MID
KIS_API_KEY=계약 후 발급값
KIS_PAY_REQUEST_URL=계약 후 제공된 공식 요청 URL
KIS_CALLBACK_SECRET=콜백 검증용 발급값
```

비밀값은 GitHub 또는 소스 코드에 커밋하지 않고 배포 환경의 Secret으로만 등록합니다.

## 반드시 끝내야 하는 결제 QA

- 성공, 사용자 취소, 한도 부족, 중복 콜백, 네트워크 타임아웃
- 승인 성공 후 예약 확정의 원자성
- 같은 거래번호의 중복 반영 방지
- 전액 취소 및 이미 취소된 거래의 재요청 방지
- 관리자 수동 상태 변경과 PG 원장 불일치 경고
- 모바일 웹뷰와 주요 국내 신용·체크카드 실결제 테스트
